# AI Assistant ML API

Python/FastAPI-сервис для предобработки английских обращений покупателей маркетплейса, классификации намерений и генерации консультационных ответов с помощью Ollama. ML-сервис вызывается основным backend по HTTP; управление заказами, пользователями и сессиями выполняется основным backend.

## 1. Требования

- Python 3.12 (см. `.python-version`) — для запуска без Docker.
- Docker и Docker Compose — для контейнерного запуска.
- Ollama с загруженной моделью `gemma4:e4b` — для генерации ответов.
- Артефакты проекта: `artifacts/classifier/models/classifier_v1.pt` и `artifacts/knowledge_db/knowledge_db_v1.csv`.
- Для запуска Ollama на CPU требуется достаточный объем оперативной памяти; ориентир из текущей конфигурации — около 8 ГБ для контейнера Ollama. На CPU генерация может занимать более 10 секунд. GPU необязателен, но может ускорить работу.

Перед запуском убедитесь, что файлы артефактов присутствуют, а порт `8000` свободен. Для Ollama по умолчанию используется порт `11434`.

## 2. Настройка

Адреса Ollama задаются переменными окружения:

| Переменная | Назначение |
|---|---|
| `OLLAMA_BASE_URL` | Основной адрес Ollama. При запуске ML API в Docker Compose по умолчанию используется `http://host.docker.internal:11434`. При локальном запуске — `http://127.0.0.1:11434`. |
| `OLLAMA_FALLBACK_URL` | Необязательный резервный адрес Ollama, если он настроен в окружении. |
| `FTLANG_CACHE` | Путь к локальному кэшу fasttext-langdetect, если предобработка не может загрузить языковые ресурсы. |

Пример настройки в PowerShell:

```powershell
$env:OLLAMA_BASE_URL = "http://127.0.0.1:11434"
$env:FTLANG_CACHE = ".\fasttext-cache"
```

При использовании Docker Compose `OLLAMA_BASE_URL` можно задать в `.env` рядом с `docker-compose.yml` или в окружении перед запуском. Не помещайте секреты и приватные адреса в публичный репозиторий.

## 3. Локальный запуск без Docker

Установите Python 3.12, затем из корня репозитория создайте виртуальное окружение:

```bash
python -m venv .venv
```

Активируйте его в зависимости от оболочки:

**Windows PowerShell:**

```powershell
.\.venv\Scripts\Activate.ps1
```

**Windows cmd:**

```cmd
.\.venv\Scripts\activate.bat
```

**Linux/macOS (Bash):**

```bash
source .venv/bin/activate
```

Установите зависимости:

```bash
python -m pip install -r requirements.txt
```

Установите и запустите Ollama (при необходимости в отдельном терминале), затем загрузите модель:

```bash
ollama serve
```

```bash
ollama pull gemma4:e4b
ollama list
```

Запустите ML API из корня проекта:

```bash
python -m uvicorn main:app --host 127.0.0.1 --port 8000
```

Если при предобработке возникает ошибка загрузки языковой модели, задайте `FTLANG_CACHE` на каталог `fasttext-cache` (при его наличии) и перезапустите API.

## 4. Запуск через Docker Compose

Стандартный запуск поднимает **только ML API**. Ollama должна быть запущена отдельно на хост-компьютере и доступна на порту `11434`.

```bash
docker compose up -d --build
```

Посмотреть вывод сервиса:

```bash
docker compose logs -f ai-assistant
```

По умолчанию контейнер подключается к Ollama через `http://host.docker.internal:11434` (настройка содержится в `docker-compose.yml`).

### Альтернатива: Ollama в отдельном Docker-контейнере

При необходимости запустите Ollama отдельно:

```bash
docker run -d -v ollama:/root/.ollama -p 11434:11434 --name ollama ollama/ollama
```

Загрузите модель:

```bash
docker exec -it ollama ollama pull gemma4:e4b
docker exec -it ollama ollama list
```

При такой конфигурации ML API в Docker Compose подключается к опубликованному на хосте порту Ollama через `host.docker.internal:11434`. Данные Ollama сохраняются в Docker volume `ollama`. Настройка GPU зависит от оборудования и платформы; см. [официальную страницу образа Ollama](https://hub.docker.com/r/ollama/ollama).

## 5. Проверка работоспособности и API

После запуска API доступен по адресу `http://127.0.0.1:8000`, интерактивная документация — `http://127.0.0.1:8000/docs`.

Проверка состояния:

```bash
curl http://127.0.0.1:8000/health
```

Ожидаемый ответ:

```json
{"status":"UP"}
```

Проверка состояния подтверждает доступность HTTP-приложения, но не гарантирует, что Ollama уже готова к генерации: прогрев модели выполняется отдельно.

**Предобработка:**

```bash
curl -X POST "http://127.0.0.1:8000/assistant/process" \
  -H "Content-Type: application/json" \
  -d '{"text":"When are the next sales?"}'
```

**Классификация:**

```bash
curl -X POST "http://127.0.0.1:8000/assistant/classify" \
  -H "Content-Type: application/json" \
  -d '{"text":"When are the next sales?"}'
```

**Генерация ответа:**

```bash
curl -X POST "http://127.0.0.1:8000/assistant/generate-answer" \
  -H "Content-Type: application/json" \
  -d '{"text":"When are the next sales?"}'
```

Команды выше рассчитаны на Bash/Linux/macOS. В Windows PowerShell можно выполнять аналогичные запросы через `curl.exe` или Swagger UI (`/docs`).

При генерации сервис самостоятельно определяет намерение. В `POST /assistant/generate-answer` можно дополнительно передать `order_context` с **уже проверенными основным backend** данными заказа. ML-сервис не должен получать сведения о чужих заказах.

## 6. Модели, инструкция и база знаний

Для работы используются следующие компоненты:

| Компонент | Текущая конфигурация |
|---|---|
| Классификатор | `artifacts/classifier/models/classifier_v1.pt` |
| База знаний | `artifacts/knowledge_db/knowledge_db_v1.csv` |
| Генеративная модель | Ollama, `gemma4:e4b` |
| Системная инструкция | Используется сервисом генерации ответов; точное расположение и способ изменения следует проверять в коде генерации. |

При обновлении классификатора или базы знаний сохраните предыдущую копию файла, поместите подготовленный артефакт в путь, который использует код, и перезапустите ML API. Для смены LLM загрузите нужную модель в Ollama и согласованно измените конфигурацию ее вызова в сервисе. При изменении системной инструкции обновите ее в соответствующем модуле и перезапустите приложение.

Перед использованием новой конфигурации проверьте `/health` и выполните тестовые запросы классификации и генерации. Версии артефактов, инструкции и модели рекомендуется фиксировать вместе с изменениями проекта. **Точные точки конфигурации модели и инструкции необходимо сверить с текущей реализацией перед изменением.**

## 7. Типовые проблемы

| Проблема | Что проверить |
|---|---|
| API не открывается на порту 8000 | Запущен ли Uvicorn/контейнер; свободен ли порт; нет ли ошибок в выводе приложения. |
| Генерация не работает | Доступность Ollama по `OLLAMA_BASE_URL`; наличие `gemma4:e4b` в `ollama list`; завершение загрузки модели. |
| Ошибка предобработки | Наличие кэша `fasttext-cache`, значение `FTLANG_CACHE`, доступность необходимых ресурсов. |
| Ошибка загрузки классификатора или базы знаний | Наличие и корректность файлов в `artifacts/`; совместимость файлов с текущей версией кода. |
| Ошибка HTTP 422 | Наличие обязательного поля `text` и корректность JSON-тела запроса. |
| Генерация выполняется медленно | Достаточность RAM и использование CPU/GPU; на CPU ответ может занимать более 10 секунд. |

При ошибках обработки проверьте сообщение API и вывод процесса. Не передавайте в журналы и обращения по поддержке реальные персональные данные покупателей без необходимости.

## 8. Остановка и перезапуск

**Локальный запуск:** остановите Uvicorn сочетанием `Ctrl+C`, затем повторите команду запуска из раздела 3.

**Docker Compose:**

```bash
docker compose stop
docker compose start
```

Полная остановка и удаление контейнера ML API:

```bash
docker compose down
```

Повторный запуск после изменения кода или Docker-образа:

```bash
docker compose up -d --build
```

**Ollama в отдельном контейнере:**

```bash
docker stop ollama
docker start ollama
```

Не удаляйте Docker volume с моделями, если хотите сохранить загруженные данные Ollama.


## 9. Логи и метрики

Логи — JSON-строки (`json_logging.py`, подключается в `main.py`):
`timestamp`, `level`, `service: "ml"`, `app_version`, `message`. `trace_id`
уже встроен в текст сообщения (как и раньше, через `X-Trace-Id` от бэкенда).

`GET /metrics` — Prometheus-метрики через `prometheus-fastapi-instrumentator`
(латентность и количество запросов по эндпоинтам). Полная схема сбора
(Grafana+Loki+Prometheus) — в корневом `MONITORING.md`.

## 10. Дополнительная информация

Сервис формирует только консультационные ответы. Управление сессиями, проверка принадлежности заказов пользователю и действия с данными маркетплейса относятся к основному backend.

Подробное описание API и схем запросов доступно в Swagger UI (`/docs`). Технические сведения об архитектуре и ограничениях системы приведены в техническом паспорте проекта.

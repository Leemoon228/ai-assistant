# Отчёт об автоматических проверках ML-backend

Запуск из корня проекта: `PYTHONPATH=. python -m pytest -q <путь_к_тестам>` (например, после копирования каталога `tests` в корень: `python -m pytest -q tests`). Тесты написаны на `pytest` и используют реальные модули ML-сервиса. Внешние вызовы Ollama, детектора языка и корректора текста в соответствующих сценариях заменяются заглушками. Для тестов архитектур моделей используется PyTorch без загрузки обученных checkpoint.

1. `test_tokenize` — проверяет токенизацию текста и нормализацию регистра.
    - 1.1) Текст `WHERE'S my ORDER #123?` преобразуется в токены `where's`, `my`, `order`, `123`.
    - 1.2) Пустая строка возвращает пустой список токенов.
    - 1.3) `Hello\nWORLD!` преобразуется в `hello`, `world`.
    - 1.4) В `Ignore 🐱 punctuation` эмодзи не попадает в список токенов.

2. `test_encode_empty_unknown_and_truncation` — проверяет кодирование текста в числовые идентификаторы для классификатора.
    - 2.1) Пустой текст получает служебный ID неизвестного токена и длину последовательности 1.
    - 2.2) Неизвестное слово кодируется ID неизвестного токена.
    - 2.3) Слишком длинная последовательность обрезается до `MAX_SEQUENCE_LENGTH`, а итоговый массив имеет требуемую длину.

3. `test_model_forward_shapes_and_finite_logits` — проверяет прямой проход моделей классификации и корректность формы выходного тензора.
    - 3.1) Архитектура `FastText` возвращает логиты формы `(2, 4)` без `NaN` и бесконечных значений.
    - 3.2) Архитектура `TextCNN` возвращает логиты формы `(2, 4)` без `NaN` и бесконечных значений.
    - 3.3) Архитектура `BiLSTM` возвращает логиты формы `(2, 4)` без `NaN` и бесконечных значений.

4. `test_unknown_architecture` — проверяет, что создание модели с неподдерживаемой архитектурой `transformer` завершается `ValueError`.

5. `test_predict_probabilities_and_mapping` — проверяет выбор наиболее вероятного намерения по логитам, преобразование вероятностей через `softmax`, допустимый диапазон `confidence` и сопоставление intent с категорией.

6. `test_knowledge_base_retrieval_and_normalization` — проверяет загрузку CSV-базы знаний и поиск статьи по intent.
    - 6.1) Intent с пробелами и другим регистром (` TRACK_ORDER `) корректно сопоставляется со статьёй `track_order`.
    - 6.2) Поиск отсутствующего intent вызывает `ValueError`.

7. `test_invalid_knowledge_base` — проверяет отклонение некорректных CSV-файлов базы знаний.
    - 7.1) Отсутствует обязательный столбец `knowledge`.
    - 7.2) Обязательное поле `knowledge` пустое.
    - 7.3) Один и тот же intent встречается дважды.
    - 7.4) В CSV есть заголовок, но нет статей.

8. `test_prompt_roles_and_grounding_instructions` — проверяет формирование сообщений для генерации ответа.
    - 8.1) Создаются сообщения с ролями `system` и `user` в ожидаемом порядке.
    - 8.2) Системный промпт содержит инструкцию отвечать на английском и ограничивающие инструкции.
    - 8.3) Пользовательский промпт содержит вопрос и предоставленный контекст заказа.
    - 8.4) Пустой пользовательский запрос вызывает `ValueError`.
    - 8.5) Вредоносная фраза `Ignore previous instructions` передаётся как пользовательский ввод; тест **не подтверждает**, что реальная LLM устойчива к prompt injection.

9. `test_generator_with_supplied_intent_skips_classification` — проверяет, что при явно переданном intent генератор не вызывает классификатор и возвращает ожидаемый тип ответа; `confidence` остаётся `None`.

10. `test_generator_classifies_when_intent_absent` — проверяет, что при отсутствии intent вызывается классификатор и полученное значение `confidence` передаётся в результат генерации.

11. `test_blank_text_bypasses_detector` — проверяет, что строка из пробелов не отправляется в детектор языка и возвращается без признака обрезки.

12. `test_non_english_rejected` — проверяет, что при определении русского языка сервис предобработки выбрасывает `UnsupportedLanguageError`.

13. `test_length_boundary_and_language_before_truncation` — проверяет ограничение длины сообщения и порядок обработки.
    - 13.1) Текст длиной ровно 300 символов не обрезается.
    - 13.2) Текст длиной 301 символ обрезается до 300, выставляется флаг обрезки.
    - 13.3) Детектор языка получает исходный текст длиной 301 символ до обрезки.

14. `test_detector_failure_rejects_fail_closed` — проверяет, что при исключении детектора языка запрос отклоняется через `UnsupportedLanguageError`, а не принимается без проверки языка.

15. `test_punctuation_preserved_when_correction_does_not_change_length` — проверяет сохранение текста `Hello, world!` и позиций знаков препинания при коррекции без изменения длины слов. До исправления предобработки этот сценарий выявлял лишние пробелы; после исправления тест прошёл.

16. `test_ollama_payload_and_answer` — проверяет HTTP-запрос к Ollama и обработку успешного ответа с подменой сетевого вызова.
    - 16.1) В запросе установлены `stream=false`, `think=false`, `options.num_predict=256`.
    - 16.2) Первое сообщение имеет роль `system`.
    - 16.3) Из ответа удаляются пробелы в начале и конце.

17. `test_empty_ollama_answer_is_error` — проверяет, что пустой или некорректный ответ Ollama приводит к `RuntimeError`.
    - 17.1) В JSON отсутствует поле `message`.
    - 17.2) Поле `message` есть, но в нём отсутствует `content`.
    - 17.3) Поле `content` содержит только пробелы.

18. `test_ollama_unavailable` — проверяет обработку ошибки соединения с Ollama (`URLError`): генерация выбрасывает понятную `RuntimeError`, а проверка доступности возвращает `False`.

## Границы

Тесты относятся **только к ML-backend**; основной backend, frontend, авторизация и права доступа не тестируются. В проверках Ollama сетевые вызовы подменены заглушками, поэтому реальная генерация, качество ответов и сетевые тайм-ауты не подтверждены. Для части проверок предобработки используются заглушки детектора языка и корректора; поведение реальных библиотек и качество исправления опечаток не подтверждены.

Тесты не загружают обученные checkpoint и не измеряют `accuracy`, `precision`, `recall`, `F1`, матрицу ошибок или качество распознавания 13 категорий на независимой выборке. Не проверены пороги уверенности для разных категорий, устойчивость к adversarial-запросам и prompt injection на реальной LLM, отсутствие утечек персональных данных, параллельная нагрузка, задержки ответа и работа с реальным контекстом заказа.

Отдельно предложенные сценарии изменения длины слова при коррекции и повторяющейся пунктуации не входят в перечисленные 28 тестовых случаев и требуют добавления в тестовый набор.

# Оценка нагрузки на оператора

Скрипт создаёт синтетические обращения по намерениям из базы знаний, отправляет их на классификацию и генерацию ответа. По ответам оценивает вероятность дополнительного вопроса и предполагаемую долю передач оператору.

## 1. Запуск и параметры

Нужны Python 3.12, запущенный API и доступная ему Ollama. Скрипты `knowledge_scenarios.py` и `operator_load.py` должны находиться в папке `scripts`.

Запуск из корня проекта:

```bash
python scripts/knowledge_scenarios.py \
  --lengths 1 --run \
  --output work/result \
  --sessions-per-day 1000 \
  --handle-minutes 8
```

Основные параметры:

| Параметр | Назначение |
|---|---|
| `--run` | Отправить обращения сервису; без него только создать CSV |
| `--output PATH` | Новый каталог результатов, обязательный параметр |
| `--base-url URL` | Адрес API; по умолчанию `http://127.0.0.1:8000` |
| `--knowledge PATH` | Путь к базе знаний; по умолчанию `artifacts/knowledge_db/knowledge_db_v1.csv` |
| `--lengths 1` | Одношаговый сценарий для расчёта вероятностной модели; по умолчанию проверяются длины `1 2 4` |
| `--variants 3` | Число формулировок на намерение: от 1 до 3 |
| `--sessions-per-day N` | Предполагаемое число сессий в день |
| `--handle-minutes N` | Среднее время обслуживания переданной сессии оператором |
| `--followup-probability P` | Задать вероятность продолжения вручную вместо оценки по ответам |
| `--clarification-mode MODE` | `question-mark` — искать `?` в ответах; `structured` — использовать поля уточнения |
| `--timeout N` | Тайм-аут запроса, по умолчанию 180 секунд |
| `--preprocess` | Включить предобработку текста через API |
| `--skip-generation` | Проверить только маршрутизацию; вероятность уточнения по ответам не оценивается |

## 2. Выходные файлы

Для `--lengths 1 --run`:

- `requests-1-turns.csv` — созданные тестовые обращения.
- `results-1-turns.jsonl` — ответы API, решения о передаче, время запросов и ошибки по каждому обращению.
- `scenarios.json` — сводная статистика и прогноз нагрузки.

## 3. Интерпретация

Главные показатели находятся в `scenarios.json → rough_probability_model`:

- `initial_human_handoff_share` (`h`) — доля немедленных передач: `human_agent` с уверенностью строго выше `0.85`.
- `p_used` (`p`) — оценка вероятности дополнительного вопроса.
- `history_handoff_probability_given_bot` — `p³`: грубая вероятность дойти до четвёртого обращения.
- `estimated_total_operator_share` — итоговая доля передач: `h + (1 − h) × p³`. Значение `0.0472` означает **4,72%**.
- `operator_sessions_per_day` и `operator_hours_per_day` — прогноз числа переданных сессий и часов работы операторов.

Раздел `scenarios → 1` показывает фактически наблюдавшиеся передачи на первом обращении; дополнительные передачи по истории в нём ещё не учитываются. `api_errors` показывает ошибки API, а `classification_by_expected_intent` — правильность классификации тестовых запросов. `null` в итоговой оценке означает, что данных для расчёта недостаточно.

## Ограничения

Это сценарная оценка: обращения синтетические, намерения представлены равномерно. По умолчанию дополнительный вопрос определяется по наличию `?`, что может давать ошибки.

Модель `p³` предполагает независимую одинаковую вероятность продолжения на каждом шаге и обязательный ответ клиента. Она трактует историю как предыдущие пользовательские сообщения; если backend считает также ответы бота, модель нужно пересмотреть. Низкая доля передач не означает высокое качество ответов.
